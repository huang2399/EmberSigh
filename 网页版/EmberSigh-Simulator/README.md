# EmberSigh 听眠 · 全功能数字孪生模拟器

> 最高级的智能，是懂得退让。

一个**完全本地、零构建、零后端**的网页数字孪生模拟器，模拟 ESP32-S3-EYE 最终硬件版本的全部功能与模块联动。所有 RMS 采样、EMA 计算、状态判断与执行器动作都来自真实运行的引擎，而非预设动画。

## 四、算法实现说明

### 1. 信号链

```
场景输入 → 虚拟麦克风包络 → Raw RMS
        → 滑动平均（默认 12 帧）→ EMA（α = 0.2）→ 迟滞状态机
```

- **滑动平均**：维护长度 `windowSize` 的环形缓冲，`AVG = Σ raw / N`。
- **EMA**：`EMA = α × AVG + (1 − α) × EMA_prev`，首帧以 AVG 初始化，避免从 0 爬升误触发。
- 模拟输入抖动采用**固定种子伪随机源**（seed 20260831），保证路演可复现；这是输入模拟，不冒充算法结果。

### 2. 迟滞三态

| 状态 | 进入条件 | 有效状态 | 执行器表现 |
|------|----------|----------|------------|
| QUIET | EMA < 安静阈 且确认完成 | QUIET | 声景播放、香氛开、灯环暖光 |
| TRANSITION | 从 DISTURBANCE 回落且 EMA < 安静阈 | **DISTURBANCE**（保留） | 仍保持退让，开始计时 |
| DISTURBANCE | EMA ≥ 噪声阈 且持续 `disturbanceHold` | DISTURBANCE | 声景淡出、香氛关、灯环暗红 |

关键设计：

1. **50～150 不是新状态**。处于阈值之间时保留此前有效状态，不新增独立状态。
2. **瞬时噪声不会造成频繁开关**。EMA 本身具有惯性，另加 0.4s 触发保持；0.1s 脉冲不会触发退让（单元测试已覆盖）。
3. **3 秒确认必须连续**。噪声再次出现时 `quietTimer` 立即归零，并记录日志。
4. **恢复必须由算法决定**。Demo Mode 在 18–24s 只把环境切回安静，不跳过确认；实际恢复时刻由引擎产生。

### 3. 统一协调器

`Coordinator.update()` 每帧读取状态机的**有效状态**，计算唯一的目标指令：

- 有效状态 = DISTURBANCE（含 TRANSITION）→ 音量 0、香氛 OFF、灯环 DIM；
- 有效状态 = QUIET → 音量 = 用户目标、香氛 ON、灯环 WARM。

低电量故障时目标音量与亮度降额到 70%。香氛恢复遵守 2s 最小停机间隔，属于安全策略而非 UI 自行决定。

## 五、路演 Demo Mode

| 阶段 | 时间 | 环境输入 | 预期系统行为 |
|------|------|----------|--------------|
| 01 | 00–06s | 安静卧室 | QUIET，声景播放、香氛开、暖光 |
| 02 | 06–12s | 轻声交谈 ≈96 RMS | EMA 上升但未越阈，保持 QUIET |
| 03 | 12–18s | 持续噪声 ≈168 RMS | EMA 越过 150，进入 DISTURBANCE |
| 04 | 18–24s | 安静卧室 | EMA < 50，进入 TRANSITION 并开始确认 |
| 05 | 24–30s | 不干预 | 满足 3s 后自然恢复，三模块平滑回归 |

演示过程中显示阶段名、倒计时、进度条、算法判断依据与实时事件日志；结束后自动停止。

## 六、尚未实现的功能清单

为保持诚实，以下功能**未实现或存在限制**：

1. **未接入真实音频文件**。项目中未发现 12 秒 PCM 森林音频资源，因此声景使用虚拟音量状态与由实时音量驱动的波形动画；界面已明确标注"虚拟音频状态"，不伪称真实录音。
2. **未连接真实 ESP32-S3-EYE**。无 Web Serial / USB 通信，所有硬件均为 Virtual HAL。
3. **产品照自带静态雾气**。原始 `hero-product.jpg` 中烘焙了雾气，无法随香氛开关消失；叠加的动态雾气粒子层与香氛卡片雾气完全受控于 MOS 状态。
4. **灯环为 2D 圆环可视化**，未做 3D 灯珠光学扩散与真实 WS2812 时序仿真。
5. **无持久化存储**。刷新页面后回到初始状态（设计如此，避免路演残留状态）。
6. **无多语言切换**；技术术语保留英文。
7. **EMA/滑动平均在噪声阈值附近的实际触发时刻受采样率影响**，这是真实滤波器行为，Demo 脚本不强行对齐秒数。

## 七、后续接入真实 ESP32-S3-EYE 的迁移建议

当前架构已按 HAL 边界分层，迁移时建议保持算法层不变，仅替换 `src/js/20-simulators.js` 中的四个虚拟类：

| 虚拟模块 | 真实替代 | 建议接口 |
|----------|----------|----------|
| `VirtualMicrophone` | ES8311 + I2S DMA | `sample(dt) → RMS`，固件侧完成 RMS 提取后串口上报 |
| `VirtualSpeaker` | MAX98357A + 3070 | `setVolume(0–100)`，I2S 播放真实森林 PCM |
| `VirtualAroma` | 光耦 MOS + D11 | `setCommand(LOW/HIGH)`，保留最小停机间隔安全策略 |
| `VirtualLight` | WS2812 × 16 @ IO16 | `update(mode, brightness)`，逐颗渐变与呼吸曲线可直接移植 |

迁移步骤建议：

1. 固件串口帧格式沿用 `RMS:<n> | STATE:<X>`，网页新增 Serial HAL 适配器，实现同样的 `sample()` 接口。
2. `Coordinator`、`StateMachine`、`SignalProcessor` **原样保留**，仅把 `ENABLE_SERIAL` 开关打开，让输入源从 Virtual HAL 切换到 Serial HAL。
3. 保留 Virtual HAL 作为开发/路演 fallback，通过 UI 上的 VIRTUAL DEVICE / REAL DEVICE 徽标切换。
4. 注意硬件约束（来自既有接线文档）：
   - **GPIO19 = USB D−，绝对禁用**；
   - I2S BCLK=IO18、LRC=IO17、DIN=IO14；
   - MOS SIG=IO1，LED DIN=IO16；
   - 加湿器独立供电，所有 GND 共地。
5. 真机上线前把 3 秒确认计时与淡入淡出斜率放到固件侧做一次一致性对照测试。

## 八、复用说明

本目录严格保护了既有原型。复用到的内容仅为：

- `images/hero-product.jpg` → 作为产品主视觉素材复制到 `src/vendor/` 并内联；
- 既有原型的设计语言（米白 / 暖金 / 松绿、衬线标题、等宽数据）→ 重新实现为更适合控制台的设计令牌；
- 既有接线文档中的 GPIO 分配与安全注意事项 → 写入迁移建议。

未复用既有原型中的随机抖动状态机（它用 `Math.random()` 直接产生 RMS 与状态），因为本任务明确要求算法真实可运行、数据来自模拟引擎。
